# Reviewer 03: tests of the protocol crates, the CLI and the endpoint (research only)

Workspace `/home/laborant/szamlazz-rs` @ 0.3.0. Every count below comes from `cargo test -p <crate> [--all-features] -- --list` on the warm build; every suite was then run once (all green: agent 197 + 6 doctests, ipn 13 + 1, adatkapcsolat 70 + 4, endpoint 45, cli 0). `restate-szamlazz` excluded per brief.

## Verdict

The protocol crates are tested well above the level the 2026-09-06 review found. The three top items that touched these crates are closed: the upstream corpus is now consumed at run time by a table-driven test that fails on an uncovered or missing file (`szamlazz-agent/tests/upstream.rs:66-98`), the vendor Adatkapcsolat example is parsed leniently *and* strictly (`szamlazz-adatkapcsolat/tests/document.rs:646-674`), the shape-vs-content rule is pinned element by element against the XSDs for all three document kinds, the fallible `KeyResolver` answers 503 with no Ack for every root, and the archiver tests run in CI via `--all-features`. The `OutcomeClass` table, VAT-rate normalisation and `try_calculated` rounding are all pinned. The remaining weaknesses are small and specific: `szamlazz-cli` has zero tests and its shipped example JSON is never checked to deserialize; eight pure-parse Adatkapcsolat tests are still needlessly behind `axum`; the IPN parser pins a *strict* date/amount policy the previous review flagged, with no captured real payload behind it; and the agent crate has no op-wide matrix for the shared header/status verdict (it is centralized, so a per-op test isn't strictly required, but a table would make the contract visible). No non-ignored test touches the network, no test calls `std::env::set_var`, and the only wall-clock dependency in a non-ignored test is harmless until the year 3000.

## 4. Fragility

- **Env vars**: no `std::env::set_var` anywhere in the five crates. Endpoint config tests use `figment::Jail` (`config.rs:489,527,545,…`, `main.rs:410`), which holds a global lock, restores env, and **changes the process cwd** to a temp dir for the closure's duration. Safe today because every other test in that binary uses absolute or compile-time paths; a future test using a relative path would race. Binary tests use `env_clear()` (`check_config.rs:355`, `stop.rs:112`).
- **Wall clock**: `archive.rs:399` `Timestamp::now()` → `tests/archive.rs:204-210` asserts the version key starts with `123456.2` (year 2xxx). Live tests use `Zoned::now()` (`live.rs:41`); ignored. No `jiff` timezone dependency in a non-ignored test; `tz-system` dev-feature exists only for `live.rs`.
- **Network**: no non-ignored test reaches szamlazz.hu (`wire.rs:14` is the only hard-coded endpoint, unused by tests). wiremock binds loopback ephemeral ports (`client.rs`, `custom_http_client.rs`, `main.rs:372,399`). `live.rs` is fully `#[ignore]`d and `cfg(feature = "client-reqwest")`.
- **Ports/signals**: `stop.rs` uses `--port 0` and binds `0.0.0.0` (passed here; a sandbox forbidding wildcard bind would fail `sigterm_stops…` and `sigint_stops…`). `check_config.rs:176` passes `--port 19080` under `--check-config`, which never binds. `stop.rs` is `cfg(unix)`: silently 0 tests on Windows.
- **Timing**: `stop.rs` 10 s start / 5 s stop, `check_config.rs` 10 s; both kill the child on timeout and print its log. Generous; observed 0.04–0.07 s.
- **Temp files**: `check_config.rs:336-340` writes fixed-name files into `CARGO_TARGET_TMPDIR` (per-crate, never cleaned; two concurrent `cargo test` processes would race on the same names; negligible).
- **Memory**: `protocol.rs:609-661` allocates three 64 MiB+ bodies and, in the `Unlimited` case, runs quick-xml over one; ~0.7 s and ~200 MB transient. Would hurt on a 512 MB CI runner.
- **Ordering**: none; tenant tests use fresh `Arc<Mutex>` per test.
- **Skips**: `upstream.rs` and `document.rs:646` skip *only* on `NotFound` of the symlink target and panic on any other IO error; the right shape. `live.rs` needs `SZAMLAZZ_AGENT_KEY`.
- **Package**: `cargo package --list -p szamlazz-agent` includes `tests/synthetic/*` via the symlink and excludes `tests/upstream/`; consistent with `SOURCES.md`.

## 5. What could be tested in more isolation

- `szamlazz-adatkapcsolat/src/axum.rs:335-380`: the request decision chain (401 → 413 → identify-400 → resolve → parse-400 → dispatch) is exercised only through `Router::oneshot`. It is fast (no socket) so this is fine, but extracting `fn decide(headers, body, resolver) -> Decision` would let the KEY_ERR/503/400 matrix be a table instead of 29 HTTP tests.
- `szamlazz-agent/src/ops/invoice.rs:1117-1210` `parse_issued` (shared by invoice/storno/query_pdf, incl. the 56-with-number recovery) is tested only via `CreateInvoice::parse`; a direct `parse_issued` matrix would be shorter than the current eight `notification_failure_*` tests.
- `restate-szamlazz-endpoint/src/main.rs` start-up log lines are asserted by spawning the binary (`check_config.rs:52-99`). The summary formatting could be a pure `fn summary(&EndpointConfig) -> Vec<String>` tested in-process, leaving the binary tests to exit codes.
- `readme.rs:47-74` `fenced()` is already pure; give it three unit tests.
